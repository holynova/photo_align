# Development handoff

This is a portrait timeline tool that runs entirely in the browser: the user imports up to 100 photos, MediaPipe Face Landmarker detects the face and both eyes, EXIF or the filename supplies the date, and the photos are sorted chronologically, aligned, and exported as a GIF or a video. The current React/Vite/TypeScript prototype builds. Most of the code lives in `src/App.tsx`, styles are in `src/styles.css`, the local model is in `public/mediapipe`, the 30-photo sample entry point is `demo/manifest.json`, and GitHub Pages is published with `npm run build:pages`, which outputs to `docs`.

Read `tasks.md` first and start from Phase 0 and Phase 1 — do not begin with a visual rewrite. The biggest risk is that `buildFrames()` keeps every full-resolution `ImageData` in memory, so exporting 30–100 photos can exhaust browser memory; GIF speed is also computed twice, once from the frame count and once from the delay. Any refactor must preserve fully local processing, multi-person selection, date editing, skipping photos, the in-page preview, and GitHub Pages sub-path compatibility.

Commit in small steps. After each task, update its status in `tasks.md` and record the verification result. At minimum run `npm ci` and `npm run build`; run `npm test` once you add tests; before releasing, run `npm run build:pages` and walk the full demo-to-export flow in a real browser. Do not commit `node_modules`, `dist`, or user test photos, and do not overwrite changes in the workspace that are unrelated to your current task.
